# Probe Bank — Module 1.3 (Induction)

## Probe: Why `addZero` is rfl but `zeroAdd` is not
Difficulty: easy
Misconception it catches: assuming commutativity is definitional
Seed question: "Why does `n + 0 = n` close with `rfl`, but `0 + n = n`
requires induction? Point to the exact definition."
Acceptable answers must mention: `Nat.add` pattern-matches on its
second argument; `n + 0` matches the base clause and returns `n`;
`0 + n` has to compute through the recursive clause for every value
of `n`.

## Probe: Choosing the induction variable
Difficulty: easy
Misconception it catches: inducting on the wrong side
Seed question: "For `(n + m) + k = n + (m + k)`, which variable
should you induct on, and why?"
Acceptable answers must mention: induct on `k`; because `Nat.add`
recurses on the right argument, inducting on `k` makes `Nat.add_succ`
applicable to both sides at once.

## Probe: The inductive hypothesis is a strong assumption
Difficulty: medium
Misconception it catches: forgetting to use the IH
Seed question: "In the `succ` case of a `Nat` induction, what does
the IH give you, and what's the typical shape of how you use it in
a `rw`?"
Acceptable answers must mention: IH : `P k` (the predecessor case);
`rw [ih]` applied after unfolding one step of the recursive
definition so that `P k` becomes visible in the goal.

## Probe: Structural vs. strong induction
Difficulty: medium
Misconception it catches: thinking strong induction is a stronger
proof system
Seed question: "Strong induction gives you an IH for all `k < n`.
Structural induction gives you an IH for `n-1`. Both are equivalent
— explain why (in one direction) and when you'd prefer strong."
Acceptable answers must mention: equivalence via packaging — strong
induction can be derived from structural by inducting on
`∀ k < n, P k`. Prefer strong when the proof of `P n` naturally uses
`P k` for some `k` not equal to `n-1` — e.g., binary splits, number-
theoretic arguments.

## Probe: Well-founded as a generalization
Difficulty: hard
Misconception it catches: thinking well-founded recursion needs `Nat`
Seed question: "Why does merge-sort's termination proof use well-
founded recursion, and what is the well-founded relation?"
Acceptable answers must mention: the two halves aren't structural
subterms of the list; the relation is "list of strictly smaller
length"; this relation has no infinite descending chain because
`length : List α → Nat` and `<` on `Nat` is well-founded.

## Probe: The hidden `[Nonempty]` requirement
Difficulty: medium
Misconception it catches: missing vacuity arguments
Seed question: "Why is `∀ xs : List α, xs = [] ∨ ∃ x xs', xs = x :: xs'`
provable without an inhabitance assumption on `α`?"
Acceptable answers must mention: we're introducing a witness from the
list, not from α itself; if α is empty the `List α` is still
well-defined (only `[]` inhabits it), so the `[]` disjunct carries the
proof. Contrast with `∀ x : α, P x → ∃ y : α, Q y` which can require
`Nonempty α`.

## Probe: When `simp` hides the induction
Difficulty: easy
Misconception it catches: reflexive reliance on automation
Seed question: "Give an example of a Nat lemma that `simp` proves in
one step but that takes a three-line `induction` proof by hand.
Which style do you learn more from writing?"
Acceptable answers must mention: `n + 0 = 0 + n` (or similar); the
hand-written proof reveals the `Nat.add` reduction pattern and the
role of the IH; `simp` is a tool, not a teacher.
