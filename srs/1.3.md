```card
module: "1.3"
tags: [nat, definition]
---
Q: Which argument of `Nat.add` does Lean's definition pattern-match on,
   and what does that mean for choosing an induction variable?
A: The second argument. `Nat.add n 0 = n` is the base clause;
   `Nat.add n m.succ = (Nat.add n m).succ` is the recursive clause.
   Induct on whichever variable needs to be "opened" for a reduction
   — usually the right-hand one.
```

```card
id: srs-1.3-rfl-vs-induction
module: "1.3"
tags: [nat, rfl]
---
Q: Why does `n + 0 = n` close with `rfl` while `0 + n = n` does not?
A: `n + 0` reduces to `n` by the base clause of `Nat.add`'s definition.
   `0 + n` has to unfold for each value of `n`, and the definitional
   reduction only handles the outer layer — induction provides the
   missing equality for every shape.
```

```card
id: srs-1.3-ih-shape
module: "1.3"
tags: [induction, tactic]
---
Q: In the successor case of an induction on `n : Nat`, what variable
   and hypothesis does `| succ k ih => ...` introduce?
A: `k : Nat` (the predecessor) and `ih : P k` (the inductive
   hypothesis that the property holds for `k`). The goal is now
   `P k.succ`.
```

```card
id: srs-1.3-strong-vs-structural
module: "1.3"
tags: [induction, strong]
---
Q: What does strong induction buy you over structural induction, and
   when would you actually reach for it?
A: IH becomes `∀ m < n, P m` — the property for every smaller value,
   not just the immediate predecessor. Use it when the proof of `P n`
   naturally references `P k` for some `k` that isn't `n-1` (e.g.,
   binary splits: `P n` from `P (n/2)`).
```

```card
id: srs-1.3-well-founded
module: "1.3"
tags: [induction, well-founded]
---
Q: A well-founded relation `r` on `α` satisfies which property, and
   why does that make recursion legitimate?
A: Every strictly decreasing chain `x₀ r⁻¹ x₁ r⁻¹ x₂ r⁻¹ ...` is
   finite — equivalently, there's no infinite descending chain. A
   recursive call must hit a smaller element, so termination is
   guaranteed by the absence of infinite descents.
```

```card
id: srs-1.3-length-append-pattern
module: "1.3"
tags: [list, induction]
---
Q: Sketch the proof pattern for `(xs ++ ys).length = xs.length + ys.length`.
A: Induct on `xs`. Nil: both sides reduce to `ys.length` (with
   `0 + ys.length` on one side, closed by `zeroAdd`). Cons `x :: xs`:
   LHS reduces to `(xs ++ ys).length + 1`, RHS to `(xs.length + 1)
   + ys.length`; IH rewrites LHS to `xs.length + ys.length + 1`,
   then `succAdd` matches the RHS.
```

```card
id: srs-1.3-reverse-uses-append-length
module: "1.3"
tags: [list, induction]
---
Q: Proving `xs.reverse.length = xs.length` requires which earlier
   lemma in its cons case, and why?
A: `lengthAppend`. `(x :: xs).reverse = xs.reverse ++ [x]`, so the
   length becomes `(xs.reverse ++ [x]).length`, which only simplifies
   via the append-length lemma.
```
